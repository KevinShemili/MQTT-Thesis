CBOR-Int uses CBOR's integer struct-tag keys instead of string field names, to isolate the extra savings from compact map keys.

Methodological note: latency is reported as mean ± 95% confidence interval across 8 independent Go benchmark runs. The confidence interval uses Student's t with df=7. Each envelope bundles a real CP-ABE ciphertext (grown from an actual TKN20 policy of the given attribute count) with a fixed-size AES-GCM nonce and ciphertext; only the marshal/unmarshal cost is timed, not the cryptography that produced the fields. Format tax is the number of bytes serialization adds over the raw field bytes.

Envelope size vs attribute count

Left: absolute envelope size, dominated by the CP-ABE ciphertext, which is why all three formats track closely together. Right: the format tax alone — bytes added over the raw payload, on a log scale. CBOR's tax is a fixed 42 bytes and CBOR-Int's is a fixed 11 bytes at every attribute count, while JSON's base64 overhead grows with payload size.
